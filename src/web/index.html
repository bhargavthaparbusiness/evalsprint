Catch prompt regressions before you ship them.

EvalSprint runs your LLM prompts against repeatable test cases, checks every response with deterministic assertions, and shows exactly which cases a prompt change fixes or breaks.

Try the demo View on GitHub

The demo runs in your browser with the mock provider: no sign-up, no API key, no model calls.

The problem

Prompt changes are code changes without tests.

A small wording change can fix one behaviour and quietly break another. Checking outputs by hand in a playground doesn't scale, and it isn't repeatable.

Built for developers who

  • iterate on system prompts and templates for an LLM feature,
  • want a fast, local check before merging a prompt change,
  • need results that are explainable, not just a score,
  • would rather keep test data in a JSON file than in a hosted platform.

How it works

Three steps, one suite file.

1

Define test cases

Each case supplies template variables and the assertions its output must satisfy.

2

Run a prompt version

Every case is rendered, sent to the provider, and checked. Each assertion explains its result.

3

Compare versions

Run two prompt versions on the same cases and see pass rates and exactly which cases changed.

Features

What's in the box

Everything below exists in the current release (v0.1). See the README for limitations and the roadmap.

Deterministic assertions

contains, not-contains, equals, regex and max-length. A case passes only if every assertion passes, and failures say why.

Mock mode

A deterministic provider that returns fixture outputs stored in the suite. Free, repeatable, and clearly labelled as not generated by a model.

Prompt comparison

Side-by-side pass rates, the change in points, and per-case fixed / regressed labels with both outputs.

CLI

init, validate, run and compare, with JSON output and exit codes you can use in CI.

Anthropic integration optional

Real model calls through the official SDK on your own instance, with the key read from the server environment only. Disabled on the public demo.

Local-first

Suites are plain JSON. The web app keeps them in your browser, and they import and export straight into the CLI.

Example

A test case is a few lines of JSON.

This case checks that a ticket summary cites the ticket ID, never promises a refund, and assigns a P2 or P3 priority. The same file runs in the web app and the CLI. 

{
  "id": "refund-request",
  "name": "Billing issue without refund promise",
  "vars": {
    "ticket_id": "T-1002",
    "ticket": "I was charged twice for my March invoice."
  },
  "assertions": [
    { "type": "contains", "value": "T-1002" },
    { "type": "not-contains", "value": "we will refund" },
    { "type": "regex", "pattern": "\\bP[23]\\b" }
  ]
}

Quick start

Run it locally in a minute.

Requires Node.js 20.12 or newer. The mock provider works immediately. To make real model calls, set ANTHROPIC_API_KEY in your environment before starting the server.

Read the full documentation →

Web app

git clone https://github.com/bhargavthaparbusiness/evalsprint.git
cd evalsprint
npm install
npm run dev   # http://127.0.0.1:5050

CLI

npm run evalsprint -- run examples/support-tickets.json
npm run evalsprint -- compare examples/support-tickets.json \
  --a baseline --b structured
